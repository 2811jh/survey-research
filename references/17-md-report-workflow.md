# 产品需求驱动的 Markdown 报告生成流程（阶段 5 分支）

> 📌 **何时读取本文档**：用户明确要求"生成 md 格式报告"、"输出 md 报告"、"产出 markdown 报告"、
> "出一份 md 报告"、"写 md 报告"等表达时，由 SKILL.md 阶段 5 指引跳转至此。
>
> 与「15-satisfaction-report.md」（默认 HTML 通用满意度模板）的区别：
> - 本文档输出 **Markdown 单文件报告**（非 HTML）
> - 框架按用户的**产品需求/业务问题**组织，不是通用满意度大盘模板
> - 每章节直接对应一个产品决策点，结论先行 + 数据支撑 + 玩家原话
> - 强制整合多源证据：量化题 + 文本归纳 + 维度对比

## 触发关键词

"md 格式报告"、"markdown 报告"、"出一份 md 报告"、"生成 md 报告"、"写 md 报告"、
"产品报告"、"决策建议报告"、"专项调研报告"等。

---

## 一、流程总览

```
1. 与用户确认产品需求与分析问题（业务问题驱动框架）
   ↓
2. 询问是否结合文本题，需要哪几道
   ↓
3. （并行）文本题主题归纳 — 调用 text_extract.py + AI 编码 + text_export.py
   ↓
4. 量化题计算 — 自动跑各题统计 + 关键 GAP/对比
   ↓
5. 整合输出 Markdown 报告（结构见下方"报告格式合同"）
   ↓
6. 输出文件清单 + 后续操作提示
```

**关键原则**：本流程是"先理解产品要什么，再去问数据"，不要直接按通用模板套数据。

---

## 二、详细步骤

### 步骤 1：理解产品需求（必做）

**目的**：搞清楚报告要回答什么业务问题——这决定章节框架。

**做法**：
1. 阅读用户描述的"产品需求/背景/想看什么"
2. 把每个具体业务问题映射到一道或几道问卷题
3. 列出"产品分析点 → 主问题 + 补充题"映射表给用户**确认**

**映射表模板**（用 ask_user_question 之前给用户看）：

```markdown
| 产品分析点 | 主问题 | 补充题 |
|---|---|---|
| 1. {业务点 A 简述} | Qx 主题目 | Qy / Qz |
| 2. {业务点 B 简述} | Qx + Qy | Qz |
| ... |
```

**如果用户没说清需求**：用 `ask_user_question` 提问。

> ⚠️ **不要跳过此步**——通用满意度模板对产品决策的支持度远低于"按业务问题组织"的框架。

### 步骤 2：与用户对齐报告框架（用 ask_user_question）

四问，逐一问，每次一个：
1. 章节结构（推荐"按产品需求分章"）
2. 是否拆人群（推荐"只看总体"）
3. 是否结合文本题，哪几道（必问，详见步骤 3）
4. 性能/非核心题组怎么处理（推荐"不放进报告"）

### 步骤 3：询问文本题分析（关键差异点）

**目的**：让用户决定哪些文本题做主题归纳。

**做法**：
1. 先调用 `text_extract.py --detect` 列出问卷里所有文本题
2. 用 `ask_user_question`（multiSelect=true）让用户选哪几道做主题归纳

**推荐项标记**：
- 直接支撑某个产品决策点的文本题 → 标"推荐"
- 与已有量化题强互补（解释"为什么"）→ 标"推荐"
- 弱相关或量极少（< 50 条）→ 标"可选"

### 步骤 4：并行执行文本归纳（subagent dispatch）

**只要用户选了 ≥ 2 道文本题，必须并行 dispatch subagent**（每题一个 `general` agent）。

**单个 subagent prompt 模板**：

```
**目标**：对 Q{N} 文本题做归纳式主题分析，作为报告 {产品分析点} 的支撑证据。

**任务**：
1. 用 `text_extract.py` 抽取（建议 sample_n=300，<300 条用 0 全量）
2. 逐条编码打标（每条 1-N 个 2-6 字简短标签）
3. 合并同义标签，聚合 4-8 个主题维度
4. 每维度选 2-3 条代表性原声
5. 写 2-3 句核心结论
6. 写 results JSON 含 details（用于 text_export.py 导出明细 sheet）
7. 调 text_export.py 导出 Excel

**参数**：
- 量化 CSV：{CSV 绝对路径}
- 列名：{完整列名}
- 抽样数：300 / 0
- Excel 输出：{输出目录}\Q{N}_{题目简称}.xlsx

**重点关注**：{结合产品决策点提示子主题方向}

**Definition of Done**：返回 Markdown：
## Q{N} {题目简称} — 文本归纳结果
**有效编码数**：N 条
**核心结论**：xxx
**维度归纳**：表格（维度名/提及数/占比/代表性原声）
**Excel 输出**：路径
```

**并行原则**：5 题及以下一次性并行 dispatch；超过 5 题分两批。

**results JSON 必含 details**：
```json
[{
  "question": "Q12.xxx",
  "conclusion": "核心结论 2-3 句",
  "dimensions": [
    {"name": "维度名", "count": 100, "percentage": "20.0%",
     "examples": ["原文1","原文2","原文3"]}
  ],
  "details": [{"text": "用户原文", "labels": "维度A, 维度B"}]
}]
```

### 步骤 5：量化数据自动计算

文本归纳进行中，**并行**用 Python 一次性算出所有需要的量化指标：

**最小必算项**：
- 各核心题的频率分布（百分比四舍五入到**整数**）
- 满意度题的均值（保留 1 位小数，如 `3.2 分`）
- 矩阵题各子项分布
- **GAP 计算**（如"当前 vs 期望"差值，单位 `pp`，整数）
- 人口学摘要：性别 / 年龄 / 职业 + 段位/活跃度（合并到样本特征段）
- **附录"调研数据说明"4 字段**：问卷标题、时间窗口、目标玩家、清洗规则
  - 未知字段必须用 `ask_user_question` 确认，**禁止瞎写**

**矩阵题语义防错**：
- 看到矩阵题先用 `pd.value_counts()` 配合文本数据**确认每个分值的语义文本**
- 不要凭题目名称推测——"频率"量表也可能是"过多/过少/合适"评估
- 量表是评估型（过多/合适/过少）时，**用业务化的"过多 X% vs 过少 Y%"对比，不要用"净评价"**

**标签反推（量化数据用数字编码，文本数据用文本标签）**：
```python
qd = pd.read_csv(quant_csv, encoding='utf-8-sig', low_memory=False)
td = pd.read_excel(text_xlsx)
q_vc = pd.to_numeric(qd[col], errors='coerce').value_counts().sort_index()
t_vc = td[col].value_counts()
pairs = {}; used = set()
for val, cnt in q_vc.items():
    best, best_diff = None, 1e9
    for lab, t_cnt in t_vc.items():
        if lab in used: continue
        d = abs(int(cnt) - int(t_cnt))
        if d < best_diff: best_diff = d; best = lab
    if best: pairs[int(val)] = best; used.add(best)
```

### 步骤 6：撰写 Markdown 报告

**必须严格按下方"报告格式合同"输出**——结构、章节、要素一个不少，禁项一个不犯。

### 步骤 7：清理 + 输出文件清单

- 删除中间 JSON（`_q*_results.json`、`_quant_data.json` 等）
- 保留：md 报告 + N 个文本分析 Excel + 原始数据
- 在回复中列出最终交付清单 + N 条核心结论（与报告核心结论数一致）
- 附加「后续操作提示」（参见 SKILL.md ⭐ 章节）

## 三、报告格式合同（强制遵守）

> 以下是本流程的**输出格式合同**。任何 md 报告必须遵守 A-K 全部规则。

### 文件命名

```
{产品名简称}_{研究主题}_{问卷ID}.md
```

例：`漫威终极逆转_Bot体验专项调研报告_94124.md`

---

### A. 顶部元信息（替换 标题+摘要+研究背景 三块）

| 项 | ❌ 不要 | ✅ 要 |
|---|---|---|
| 报告大标题 | `# 《XXX》调研报告` | 不写（文件名已表达） |
| Emoji 引导符 | `📊 🎯 🕐` | 不写 |
| 生成时间 | `🕐 生成时间：YYYY-MM-DD` | 不写 |
| 研究目的 | `（A）xxx ｜（B）xxx` 长句 | 4-5 个 4-7 字动作短语 |
| 元信息后分隔 | `---` | 不写，直接接核心结论 |

**固定模板**：

```markdown
> **样本量**：N 份 ｜ **数据周期**：YYYY-MM-DD ~ MM-DD ｜ **问卷 ID**：xxx
>
> **研究目的**：动作短语1 ｜ 动作短语2 ｜ 动作短语3 ｜ 动作短语4
```

---

### B. 核心结论（替换 「📌摘要+三句结论+三条建议」）

| 项 | ❌ 不要 | ✅ 要 |
|---|---|---|
| 标题 | `## 📌 摘要` + 三层结构 | 单层 `# 核心结论` |
| 数量 | 固定 3 句 + 3 条建议 | **N = 业务问题数 + 1** |
| 建议矩阵 | 后跟 3 条建议表 | 删除（合并到结论 bullet） |
| 格式 | 行内长句 | **首行强论断 + 4 空格缩进 bullet** |

**每条结论标准格式**：

```markdown
N. **强论断**（括号通俗注解）——延展说明

    - 子要点 1——原因/数据
    - 子要点 2——原因/数据
    - 子要点 3——原因/数据
```

**规则**：
- 首行整句粗体，**括号注解不粗体**
- bullet **4 空格缩进**（不是 2 空格）
- bullet 用 `——`（中文长破折号）接释义
- **支持"夹答复"**：若某结论含多个产品决策问题，直接缩进列出 `→ 是/否 + 数据`：

```markdown
3. **对抗强度调整需符合玩家认知：上分快、情绪缓冲、做任务快**

    - 降低必胜 Bot？→ 不建议降（减负、轻松愉快更符合玩家认知）
    - 减少撤退？→ 是（54% 玩家觉得偏多）
    - 增加 SNAP？→ 建议小幅增加（40% 玩家觉得偏少）
```

---

### C. 章节命名与编号

| 项 | ❌ 不要 | ✅ 要 |
|---|---|---|
| 编号方式 | `一、二、三` 中文 | `# 1.` `# 2.`（**阿拉伯+点+空格**） |
| 子标题 | `### 3.1`（一位小数无末尾点） | `## 1.1.` / `### 2.1.1.`（**每级末尾点**） |
| 章节名长度 | "场景投放策略 ← 产品需求 A" | 4-7 字极简："Bot 对局场景" |
| 产品需求标注 | `← 产品需求 A` | 删除 |
| 题号标注 | `（Q9 vs Q10）` 进标题 | 删除（题号不进标题） |
| ★ 重点标记 | `### 3.2 ★ xxx` | 删除 |
| 决策问题章节 | 段落级 `#### ① xxx` | **三级标题 `### 2.2.1. 是否要降低 xxx？`**（带问号） |
| 用户画像位置 | 第 2 章 | **永远放最后一章** |
| 研究背景章节 | `## 一、研究背景与方法` | **整章删除**（元信息块代替） |

---

### D. 章节内部写法

**D1. 每节首行 = 强论断 bullet + 4 空格缩进展开**

```markdown
- **近两周，有84%玩家感知遇到过人机对手，超3成高频遭遇**（占35%）
    - 频率：其中35%经常遇到，35%偶尔，14%很少，仅6%从未遇到
```

**D2. 决策问题节首行 = 整行加粗答复**

```markdown
**→ 是，需减少撤退频率。54%的玩家感到人机中途撤退偏多，"加倍就跑"有损对局体验**

- 原因1：约**20%**玩家对Bot「一加倍就跑、要赢就撤退」感到不满（**Top3不满**）
- 原因2：约**15%**玩家明确建议「优化撤退机制」（**Top5建议**）
```

- → 箭头**包括在粗体内**
- 不同决策点**详略不均**：争议小的只配原话，争议大的展开数据+原因

**D3. 章节末禁写「📌 章节建议」块**——建议融入正文答复中

---

### E. 数据呈现

| 项 | 规则 |
|---|---|
| 百分比精度 | **只到整数**（46% 而非 46.4%）。均值保留 1 位小数（3.2 分） |
| 分布展示 | **优先用截图柱状图**（`![图片](popo链接)`），文中只配一句强论断 |
| 表格使用 | **极少**——仅 GAP 对比/矩阵汇总/数据说明三种场景 |
| 表头语言 | 业务化："当前场景" / "差值" / "是否增加投放"（不写 "GAP" / "决策方向"） |
| 表头注解 | 括号写 `<br/>（业务化解释）`，不写 `(Q9, n=5086)` |
| 样本量 | **不进表格** |
| 决策列措辞 | **模糊词**："可考虑增投" / "适度增投" / "-"。**禁用**"大力增投" / "维持" |
| 表格 emoji | 仅保留 `🔺`（差值列），**禁用** `🟢🟡🔴⚪` |
| 粗体高亮 | **所有关键阈值单元格**（如 Q16 表里"过多/过少"高占比都加粗） |
| 矩阵题表头 | **完整问句作首列表头**："Q：与人机(Bot)对战时，您遇到以下对局的频率是？" |
| 决策列单独列 | **不要**——决策已在上方答复中 |

---

### F. 文本归纳块（开放题）

**F1. 首行 = 一句强结论（3 个并列业务概念）**——**不写"核心结论："前缀**：

```markdown
- **玩家核心不满原因： 赢得不爽**（不给8分）**，输得憋屈**（感觉Bot全程开透+精准反制+现场印卡）**，玩得无聊**（卡组同质）
```

**F2. 缩进 3 条 bullet 业务化展开**（把 AI 编码的 8 维度归纳**压缩为 3 大概念**）：

```markdown
    - 关键词1——具体描述（玩家口吻）；
    - 关键词2——具体描述（玩家口吻）；
    - 关键词3——具体描述（玩家口吻）。
```

**F3. 配截图柱状图**（如文本归纳已量化）

**F4. 配 2-3 条玩家原话**（强制）：

```markdown
> *玩家原话：*"原话内容"
>
> *玩家原话：*"原话内容"
>
> *玩家原话：*"原话内容"
```

- 独立 `>` 引用块，中间空 `>` 行
- 前缀 `*玩家原话：*`（italic + 中文冒号）
- 选**鲜活、口语化、带情绪**的句子
- **禁标 Q12/Q19** 题号

**F5. 附件挂载**（每个文本归纳必带）：

```markdown
[Q12_Bot不满原因.xlsx](附件链接)

*\*详见独立 Excel：**`Q12_Bot不满原因.xlsx`*
```

**F6. 禁写「排名/维度/占比/代表性原声」8 行细分表**——只放在 Excel 里

### G. 用户画像章节（最后一章）

**G1. 固定两小节结构**：
- `## N.1. 近期对局感受（含pvp）`
- `## N.2. 人口学信息`

**G2. N.1 近期对局感受**：把"难度感知 / 被反制感 / Bot 灵活度感"等**环境感受题**放这里（不放业务章节）：

```markdown
- 整体偏难。41%觉得偏难，仅12%觉得偏简单。

![图片](柱状图链接)
```

**G3. N.2 人口学信息**：
- 开头 `📝 **样本特征**：xxx` 总结段（**整份报告唯一保留 emoji 之一**）
- 下面分 3 项：**性别 / 年龄 / 职业**（仅 3 项基本人口学 + 截图）
- **段位 / 时长**等行为变量并入"样本特征"段，**不单列**

### H. 附录

**H1. 只保留 2 块**（删 3 块）：
- `## 附1-产品需求原文`
- `## **附2-调研数据说明**`
- ❌ 删 "文本 Excel 清单"（已挂正文）
- ❌ 删 "原始数据路径"
- ❌ 删 "暂未展开题目"
- ❌ 删 "📋 报告生成方法"

**H2. 附 1 格式**：**双重引用 `>>`** 嵌套原文照搬 + 末尾贴产品截图 + `*\*附图为程序建议调研题目*`

**H3. 附 2 格式**（强制 4 行表）：

```markdown
> 问卷ID: `xxx` ｜ 数据回收周期: `YYYY-MM-DD ~ YYYY-MM-DD` ｜ 有效样本: **N 份**

| 项目 | 内容 |
| --- | --- |
| **数据来源** | 《产品名》研究主题（赛季/版本/期次），问卷 ID：xxx |
| **时间窗口** | YYYY-MM-DD 至 YYYY-MM-DD |
| **目标玩家** | 目标人群描述，累计回收 N 份 |
| **数据清洗** | 清洗规则描述 |
```

**H4. 报告末尾**：`---` 分隔线 + `END` 字样

### I. Emoji / 符号 / 标点规则

| 类别 | ❌ 严禁 | ✅ 允许 |
|---|---|---|
| 装饰性 emoji | 📊🎯🕐🔴🟢🟡⚪🔍📌★🚨 | **仅 2 处保留**：📝（样本特征段）、→（决策答复） |
| 表格内 emoji | 🟢🔴⚪ 决策图标 | `🔺` 差值列（少量） |
| 引号 | `「」` | `""`（全角双引号） |
| 破折号 | `--` 或 ` — ` | `——`（中文长破折号） |
| 列表分号 | `;` | `；`（中文分号） |
| 强调符号 | `★` / `🚨` 视觉强调 | 仅靠**粗体** |

### J. 业务语言替换表

| ❌ 指标语言 | ✅ 业务语言 |
|---|---|
| 满意度 3.16/5 | 满意度 3.2 分 |
| 净推荐值/NPS | （不出现） |
| 净评价 / GAP | 差值 / 缺口 / pp 数 |
| 双峰分化 / 单向心智 | （不出现，直接看现象） |
| 大力增投 / 大幅减少 | 可考虑增投 / 需减少 |
| 维持现状 | - |
| 🔍 关键洞察 / 核心发现 | （不写，直接结论） |
| 数据依据 / 预期收益 | （不出现在正文） |
| 关键回合反制精准得离谱 | 输得憋屈、开透视、印卡作弊感 |

**业务概念词推荐使用**：
- 体验类：上分快 / 做任务快 / 赢得不爽 / 输得憋屈 / 玩得无聊
- 功能类：减负 / 情绪缓冲 / 轻松愉快 / 训练助手 / 吃到 8 分 / 没爽到
- 评价类：偏多 / 偏少 / 合适 / 缺口 / 错位

## 四、强制要素清单

| 要素 | 必须 | 说明 |

## 五、写作风格规则

1. **结论先行**：每个小节首行直接给结论，再展开数据
2. **业务化压缩**：把 N 个细分维度压成 3 个并列业务概念
3. **百分比整数化**：46% 不写 46.4%；均值 1 位小数（3.2 分）
4. **强调用粗体**：禁用 ★ 🚨 ✨ 等装饰，关键词用 `**`
5. **括号注解不粗体**：粗体只包关键词，括号通俗解释在粗体之外
6. **答复式表述**：决策问题节用 `**→ 是/否，原因+数据**` 整行加粗
7. **建议必须可落地**：避免"提升 xx"——要写具体到可执行
8. **题号不入正文**：Q12/Q19 等只出现在文本归纳附件名里
9. **保持极简**：250-300 行是上限；超过先砍正文，不砍原话

## 六、常见错误与规避

| 错误 | 规避 |
|------|------|
| 直接套通用满意度模板 | 必须先做步骤 1 与用户对齐产品需求 |
| 文本题只抽 5 条原声 | 必须用 subagent 做主题归纳，返回维度+占比+原声 |
| 单选题显示"选项1/选项2" | 用文本数据 xlsx 反推标签映射（步骤 5） |
| **矩阵题量表语义瞎猜** | 看到矩阵题先用 `value_counts` 配文本数据确认每个分值语义；不确定时 `ask_user_question` 让用户确认 |
| **章节命名超长**（带"← 产品需求 A"） | 限 4-7 字极简命名 |
| **数字编号用中文**（一、二、三） | 用阿拉伯数字+点+空格 `# 1.` |
| **用户画像放第 2 章** | 永远放最后一章 |
| **保留"研究背景与方法"独立章节** | 元信息块代替，整章删除 |
| **章节末写"📌 章节建议"块** | 建议融入正文答复中 |
| **综合行动建议矩阵** | 删掉，每章节末嵌入 `→ 答复` 即可 |
| **装饰性 emoji 满屏**（🔴🟢🟡⚪★） | 全砍，仅保留 📝（样本特征）+ →（答复） |
| **百分比小数 46.8%** | 改成整数 47%（均值除外） |
| **量化分布用表格列全选项** | 优先用截图柱状图 + 一句话浓缩 |
| **决策列用"大力/维持"强语气** | 改用"可考虑增投/适度增投/-" |
| **样本量 n=xxx 进表格** | 表格不写样本量 |
| **题号 (Qx) 进标题** | 题号不入标题 |
| **报告超过 350 行** | 砍正文方法论描述，保留原话和图片 |
| **附录列 4 块以上** | 仅保留产品需求原文 + 调研数据说明 |
| **数据说明附录字段瞎填** | 4 字段未知必须 `ask_user_question` 让用户确认 |
| **正文出现方法论术语**（净评价/GAP/双峰） | 改为业务语言（差值/缺口/偏多偏少） |
| **中间 JSON 文件遗留输出目录** | 步骤 7 必须清理 |
