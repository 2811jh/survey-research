# 产品需求驱动的 Markdown 报告生成流程（阶段 5 分支）

> 📌 **何时读取本文档**：用户明确要求"生成 md 格式报告"、"输出 md 报告"、"产出 markdown 报告"、
> "出一份 md 报告"、"写 md 报告"等表达时，由 SKILL.md 阶段 5 指引跳转至此。
>
> 与「15-satisfaction-report.md」（默认 HTML 通用满意度模板）的区别：
> - 本文档输出 **Markdown 单文件报告**（非 HTML）
> - 框架按用户的**产品需求/业务问题**组织，不是通用满意度大盘模板
> - 每章节直接对应一个产品决策点，结论先行 + 数据支撑 + 行动建议
> - 强制整合多源证据：量化题 + 文本归纳 + 维度对比

## 触发关键词

"md 格式报告"、"markdown 报告"、"出一份 md 报告"、"生成 md 报告"、"写 md 报告"、
"产品报告"、"决策建议报告"、"专项调研报告"等。

---

## 一、流程总览

```
1. 与用户确认产品需求与分析问题（业务问题驱动框架）
   ↓
2. 询问是否结合文本题，需要哪几道
   ↓
3. （并行）文本题主题归纳 — 调用 text_extract.py + AI 编码 + text_export.py
   ↓
4. 量化题计算 — 自动跑各题统计 + 关键 GAP/对比
   ↓
5. 整合输出 Markdown 报告（结构见下方）
   ↓
6. 输出文件清单 + 后续操作提示
```

**关键原则**：本流程是"先理解产品要什么，再去问数据"，不要直接按通用模板套数据。

---

## 二、详细步骤

### 步骤 1：理解产品需求（必做）

**目的**：搞清楚报告要回答什么业务问题——这决定章节框架。

**做法**：
1. 阅读用户描述的"产品需求/背景/想看什么"
2. 把每个具体业务问题映射到一道或几道问卷题
3. 列出"产品分析点 → 主问题 + 补充题"映射表给用户**确认**

**映射表模板**（用 ask_user_question 之前给用户看）：

```markdown
| 产品分析点 | 主问题 | 补充题 |
|---|---|---|
| 1. {业务点 A 简述} | Qx 主题目 | Qy / Qz |
| 2. {业务点 B 简述} | Qx + Qy | Qz |
| ... |
```

**如果用户没说清需求**：用 `ask_user_question` 提问，例如：
- "请简述这份调研的核心业务问题——你希望报告回答几个产品决策？"
- "我能否假设这份报告要支撑以下三个决策：xxx / yyy / zzz？"

> ⚠️ **不要跳过此步**——通用满意度模板对产品决策的支持度远低于"按业务问题组织"的框架。

### 步骤 2：与用户对齐报告框架（用 ask_user_question）

**问 1：章节结构**

```
框架整体结构你怎么看，哪一种最贴合你的使用场景？
- 按产品需求分章（推荐）：每章独立可读，直接对应一个业务决策
- 按需求合并：相似主题合并成一章，章节更紧凑
- 结论倒金字塔：摘要先行，老板友好
- 其他/再讨论
```

**问 2：是否拆人群（交叉分析）**

```
每章的数据是否需要按人群拆分（交叉分析）？
- 只看总体，不拆人群（推荐）
- 拆段位/性别/付费等级 等
- 全维度都拆（详尽但报告变长）
```

**问 3（关键！）：是否结合文本题，哪几道**

详见步骤 3。

**问 4：性能/非核心题组怎么处理**

```
某些与核心研究主题弱相关的题组（如性能题/弱相关人口学）怎么处理？
- 不放进报告（推荐）
- 附录里列简表
- 独立一章详细展开
```

### 步骤 3：询问文本题分析（关键差异点）

**目的**：让用户决定哪些文本题做主题归纳，作为"为什么"的证据来源。

**做法**：
1. 先调用 `text_extract.py --detect` 列出问卷里所有文本题
2. 用 `ask_user_question`（multiSelect=true）让用户选哪几道做主题归纳

**示例提问**：

```
共检测到 N 道文本题。哪几道做主题归纳分析？（多选）
- Q12 不满意 Bot 的原因（推荐，支撑 B-强度+卡组不满的「为什么」）
- Q19 关于人机的其他建议（推荐，涵盖 B+C 多面建议）
- Q22 陪练模式期待/顾虑（推荐，直接支撑 C-陪练模式功能设计）
- Q13 满意原因 / Q23 不对劲对手（补充，可选加）
```

**给出推荐项的依据**：
- 直接支撑某个产品决策点的文本题 → 标"推荐"
- 与已有量化题强互补（解释"为什么"）→ 标"推荐"
- 弱相关或量极少（< 50 条）→ 标"可选"

**用户全选/部分选/不选都尊重，不强制**。

### 步骤 4：并行执行文本归纳（subagent dispatch）

**只要用户选了 ≥ 2 道文本题，必须并行 dispatch subagent**（每题一个 `general` agent）。

**单个 subagent prompt 模板**（参考 SKILL 提供的 task 工具调用方式）：

```
**目标**：对 Q{N} 文本题做归纳式主题分析，作为 报告 {产品分析点} 的支撑证据。

**效力**：deeper pass（逐条编码 + 聚合维度 + 写结论 + 导出 Excel）

**任务**：
1. 用 `text_extract.py` 抽取（建议 sample_n=300，<300 条用 0 全量）
2. 逐条编码打标（每条 1-N 个 2-6 字简短标签）
3. 合并同义标签，聚合 4-8 个主题维度
4. 每维度选 2-3 条代表性原声
5. 写 2-3 句核心结论
6. 写 results JSON 含 details（用于 text_export.py 导出明细 sheet）
7. 调 text_export.py 导出 Excel

**参数**：
- 量化 CSV：{CSV 绝对路径}
- 列名：{完整列名}
- 抽样数：300 / 0
- Excel 输出：{输出目录}\Q{N}_{题目简称}.xlsx
- 临时 JSON：同目录 `_q{N}_results.json`

**重点关注**：{结合产品决策点提示子主题方向，让 AI 不要瞎归纳}
例如：「玩家不满 Bot 的核心抱怨——强度/卡组/行为感知/对局结果分布？」

**Definition of Done**：返回 Markdown：
## Q{N} {题目简称} — 文本归纳结果
**有效编码数**：N 条
**核心结论**：xxx
**维度归纳**：表格（维度名/提及数/占比/代表性原声）
**Excel 输出**：路径
```

**并行原则**：5 题及以下可一次性并行 dispatch；超过 5 题分两批。

**results JSON 格式**（必须含 details 才能让 text_export.py 导出 AI 编码的明细 sheet）：

```json
[{
  "question": "Q12.xxx",
  "conclusion": "核心结论 2-3 句",
  "dimensions": [
    {"name": "维度名", "count": 100, "percentage": "20.0%",
     "examples": ["原文1","原文2","原文3"]}
  ],
  "details": [{"text": "用户原文", "labels": "维度A, 维度B"}]
}]
```

### 步骤 5：量化数据自动计算

文本归纳进行中，**并行**用 Python 一次性算出所有需要的量化指标，写到中间 JSON：

**最小必算项**：
- 各核心题的频率分布（单选/多选）
- 满意度题的均值 + 满意/中性/不满占比
- 矩阵题的各子项均值 + 高/中/低占比
- 关键 **GAP 计算**（如"当前 vs 期望"对比）
- 人口学摘要（性别 / 年龄 / 段位 / 时长）

**注意标签映射**：单选题如果不含语义标签（编码为 1/2/3/4/5），从**文本数据 xlsx** 反推标签——
按 value_counts 频次匹配编码与文本标签（参考下方代码模板）。

```python
# 反推标签映射（量化数据用数字编码，文本数据用文本标签）
qd = pd.read_csv(quant_csv, encoding='utf-8-sig', low_memory=False)
td = pd.read_excel(text_xlsx)
q_vc = pd.to_numeric(qd[col], errors='coerce').value_counts().sort_index()
t_vc = td[col].value_counts()
pairs = {}; used = set()
for val, cnt in q_vc.items():
    best, best_diff = None, 1e9
    for lab, t_cnt in t_vc.items():
        if lab in used: continue
        d = abs(int(cnt) - int(t_cnt))
        if d < best_diff: best_diff = d; best = lab
    if best: pairs[int(val)] = best; used.add(best)
```

### 步骤 6：撰写 Markdown 报告

**必须严格按下方"报告模板"输出**——结构、章节、要素一个不少。

### 步骤 7：清理 + 输出文件清单

- 删除中间 JSON（`_q*_results.json`、`_quant_data.json` 等）
- 保留：md 报告 + N 个文本分析 Excel + 原始数据
- 在回复中列出最终交付清单 + 三句核心结论 + 三条产品建议
- 附加「后续操作提示」（参见 SKILL.md ⭐ 章节）

### 强制要素清单

每份 md 报告**必须**包含：

| 要素 | 必须 | 说明 |
|------|:---:|------|
| 📌 摘要（三句结论 + 三条建议） | ✅ | 老板/PM 5 秒能看懂 |
| 一、研究背景与方法 | ✅ | 含分析框架映射表 |
| 二、用户/玩家画像 | ✅ | 含样本偏向说明 |
| 业务点章节（≥ 2 个） | ✅ | 严格对应产品需求 |
| 每章 📌 章节建议 | ✅ | 章末小结的可执行建议 |
| 综合行动建议（含优先级矩阵） | ✅ | 跨章节决策表 |
| 附录（含独立 Excel 清单 + 原始数据路径） | ✅ | 可追溯 |
| ★ 标记关键发现点 | ✅ | 至少 3 处 ★ |
| 🟢/🟡/🔴 颜色标记 | ✅ | 健康/警告/预警分级清晰 |
| 数据依据（具体题号+数值） | ✅ | 所有结论必须有题号/百分比支撑 |

### 写作风格要求

1. **结论先行**：每个小节先给结论，再列数据
2. **数据具体**：所有占比写到一位小数（如 46.8%），不要写"近一半"
3. **题号引用**：所有结论标 (Qx) 或 (Qx + Qy) 表明数据出处
4. **强调关键数字**：用 **加粗** 突出 Top1 / Top3 / 极端值
5. **避免通用废话**：不要写"建议加强 xxx"——必须写具体到可执行的建议+依据题号
6. **建议必须可落地**：避免"建议提升用户体验"——要写"在玩家已加倍的对局中，强制 Bot 不再撤退"
7. **不要写"成功"而是写"完成"**：never declare 'success' without verification

## 四、常见错误与规避

| 错误 | 规避 |
|------|------|
| 直接套通用满意度模板，没问业务问题 | 必须先做步骤 1 与用户对齐产品需求 |
| 文本题只抽 5 条原声当原话 | 必须用 subagent 做主题归纳；返回维度+占比+原声 |
| 单选题选项显示"选项1/选项2"而非语义标签 | 用文本数据 xlsx 反推标签映射（步骤 5） |
| 章节结构按"满意度→NPS→细分→声音→预警→建议" | 章节结构按产品需求 A/B/C 组织 |
| 建议只写"提升 xx"没有数据依据 | 每条建议带题号+数据，并在优先级矩阵中给出 |
| 中间 JSON 文件遗留在输出目录 | 步骤 7 必须清理 |
