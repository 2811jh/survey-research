# 文本分析工作流程（阶段 4）

> 📌 **何时读取本文档**：用户要求分析文本题/开放题时，由 SKILL.md 阶段 4 指引跳转至此。

## 触发条件

- 用户要求分析文本题 / 开放题
- 用户说"请结合文本题分析"
- 用户要求全面分析且数据中存在文本题

## 核心方法论

采用**归纳式（自下而上）**分析——先逐条编码打标，再从标签中聚合维度，
最后统计和总结。**严禁**先定义维度再打标（演绎式），维度必须从数据中自然涌现。

## 流程连续性

300 条抽样文本读取完成后，**自动连续执行**后续所有步骤（编码 → 聚合 → 统计 → 导出 → 报告），
中途不要停下来询问用户。全部报告生成完毕后，才在最后提示用户还可以做什么。

## 执行步骤

### 1. 检测文本题

如果阶段 1 已有结果可跳过，否则执行：
```bash
python {SKILL_DIR}/scripts/text_extract.py --file_path "用户文件路径" --detect
```

### 2. 提取文本（默认随机抽样 300 条）

对每道需要分析的文本题，默认随机抽取 300 条清洗后的有效文本：
```bash
python {SKILL_DIR}/scripts/text_extract.py \
  --file_path "用户文件路径" \
  --column "Q10.您还有什么建议？" \
  --sample_n 300
```
返回 JSON 包含清洗后的文本列表（含 `valid_count` 总有效条数）。

> ⚠️ **默认取 300 条随机有效文本**，仅当用户明确要求"全量分析"时才使用 `--sample_n 0`。
> 300 条抽样在 95% 置信水平下误差约 ±5.7%，对主题发现已足够。

### 3. 逐条开放编码（打标）（你来做）

阅读全部抽样文本，**逐条**为每条文本分配 1~N 个简短标签。

**关键原则**：
- **不要预设任何分类框架**，让标签从文本内容中自然涌现
- 标签用简短词组（2-6 字），如"加载慢"、"画面模糊"、"客服态度差"
- 一条文本可以有多个标签（多标签编码）
- 无实质内容的文本标为"无效/模糊"
- 遇到新主题随时创建新标签，不要硬套已有标签

输出格式（每条文本一行）：
```
[1] "希望游戏不要那么卡" → 卡顿, 性能优化
[2] "客服回复太慢了" → 客服响应慢
[3] "挺好的没什么建议" → 无效/模糊
...
```

> 📖 **参考** `references/01-thematic-analysis.md`：按六步流程归纳主题。
> 📖 **参考** `references/02-affinity-mapping.md`：不要预设分类，让维度从数据中自然涌现；保留异常点不要强行归类。

### 4. 标签合并与维度聚合（你来做）

编码完成后，审视所有涌现的标签：
- **合并同义标签**：如"加载慢"和"卡顿"合并为"性能/卡顿"
- **聚合为 4-8 个主题维度**：将相似标签归入同一维度
- **保留"其他"维度**：无法归类的少量标签放入"其他"

### 5. 统计与结论（你来做）

基于打标结果进行统计：
- **计算各维度**：提及条数（count）和占比（percentage），占比 = 该维度条数 / 有效抽样总数
- **选取典型原声**：每个维度选 2-3 条最具代表性的用户原文
- **撰写核心结论**：2-3 句话总结主要**定性发现**（如"版本更新节奏与模组定价是两大集中诉求"）

> ⚠️ **结论里不要手写百分比/条数**：导出脚本会以 details 为唯一数据源自动重算各维度
> 数字，并在结论末尾追加一行「【数据佐证（脚本自动计算，N=…）】」。你只负责写定性判断，
> 数字交给脚本回填，避免结论数字与表格互相矛盾。

> 📖 **参考** `references/04-interview-analysis.md`：识别回答中的"强度信号"（情感语言、反复提及、变通方法），高强度回答应在维度示例中优先展示。

### 6. 导出文本分析 Excel

将分析结果写入临时 JSON 文件，然后调用导出脚本。

```bash
python {SKILL_DIR}/scripts/text_export.py \
  --output_path "{文件目录}/{简短题意文件名}.xlsx" \
  --results_file "临时JSON文件路径"
```

文件命名默认使用「题号_简短题意.xlsx」，避免统一命名为“文本分析”。例如：
- `Q5_MC满意原因.xlsx`
- `Q8_外挂表现.xlsx`
- `Q20_版本建议.xlsx`
- `Q98_不推荐原因.xlsx`

如果未传 `--output_path`，`text_export.py` 会根据 results JSON 的 `question` 自动生成上述风格的默认文件名，保存在当前工作目录。

results JSON 格式：
```json
[{
  "question": "Q10.您还有什么建议？",
  "conclusion": "核心定性结论（不写数字）",
  "dimensions": [
    {"name": "维度名", "examples": ["原文1", "原文2"]}
  ],
  "details": [
    {"text": "用户原文", "labels": "维度A, 维度B"}
  ]
}]
```

> 🔒 **details 是必填项（硬制）**：抽样模式下必须把 Step 3 逐条编码的结果全部填入 `details`，
> 否则脚本直接返回 `error_type=missing_details` 并拒绝出表。这样能保证：
> 1. 逐条明细就是 AI 的真实编码（准确度最高）；
> 2. 总结概览的 count/percentage 全部由脚本**从 details 反算**（单一数据源，两个 sheet 永不矛盾）；
> 3. 结论数字由脚本回填，杜绝幻觉。
>
> `dimensions` 里的 `count`/`percentage` 可以不填——脚本会忽略并重算；只需给 `name` 和
> `examples`（examples 缺失时脚本会自动从命中该维度的真实原文里补）。
>
> **"其他/未归类" 会被显式展示**：脚本自动把 `其他`、`无效/模糊` 等各种叫法合并为统一的
> 「其他/未归类」桶，并在总结概览中单独成行（不再隐藏）。若该桶占比 > 20%，脚本会在返回
> JSON 的 `warnings` 中提示——此时应回头补充维度或重新编码，把可归类的文本从"其他"里救出来。

### 7. 与交叉分析关联（如果同时执行了交叉分析）

结合两者结果形成综合洞察。例如：
- "不满意的用户（交叉分析显示男性占比更高）主要反映了 XX 问题（文本分析维度 1）"
- "付费用户对 XX 的关注度明显高于免费用户（交叉分析差异 15pp），文本中体现为..."

## 全量文本分析

如果用户后续要求全量分析，则以 `--sample_n 0` 重新调用 text_export.py：

```bash
python {SKILL_DIR}/scripts/text_export.py \
  --output_path "{文件目录}/{文件名}_文本分析.xlsx" \
  --results_file "临时JSON文件路径" \
  --file_path "原始数据文件路径" \
  --sample_n 0
```

这会对全量文本进行关键词规则标注，并重新统计维度 count/percentage。

> ⚠️ **全量标注局限性**：规则标注基于关键词匹配，覆盖率通常低于 AI 编码（约 40-60% 的文本可被自动标注，
> 其余标为"其他"）。为提高覆盖率，在 results JSON 的 examples 中尽可能多提供典型原声（6-10 条），
> 这些原声中的关键词会被自动提取作为匹配规则。
